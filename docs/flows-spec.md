# Heybe 三个核心流程交互规格（v1）

> 写法参照 Julie Zhuo 的体验优先方法：先写用户的目标和应有的感受，再写步骤、全部状态（空、加载、出错、边界）、文案和成功标准，最后给出技术负责人可以直接实现的验收标准。
> 约束：沙箱默认开启；阶段 1 只做 LLM 核心（没有渠道、浏览器自动化、对外发送）；桌面端是自研的 Tauri+React 应用，不使用 FastClaw 前端，只调用 `/v1`。
> 文案面向从没用过 AI 助理的普通人：不出现 Agent、模型、API、Token、沙箱、MCP 等词。下文的"界面用词"列是唯一可以展示给用户的说法。

## 0. 用词表（工程 → 界面）

| 工程概念 | 界面用词 |
|---|---|
| Agent | 助理 |
| 模型提供方 / API key | "AI 服务"/"连接码"（首次出现时附一行说明："由 AI 服务商提供的一串字符，就像你的会员卡号"） |
| 本地模型 (Ollama) | "在这台电脑上运行（不联网）" |
| 云模型 | "使用在线 AI 服务" |
| 沙箱 | "安全空间：它只能在给它的文件夹里工作" |
| 授权目录 | "给它用的文件夹" |
| 任务 / 待验收 | "交给它的事"/"等你看一眼" |
| 审批 | "要先问你" |

## 流程一：首次使用

**所属 Issue：** #19 T1.3.1（聊天主体）、#40 E5.1（引导，v1 前移的极简版）、#6 T0.3.1（安全空间检查）、#16 T1.2.1（连接测试）

### 1.1 用户目标与应有体验
- 目标："装好以后，马上让它帮我做一件事。"
- 应有的感受：三步以内就能开始说话；不需要懂任何技术；清楚地知道"我的东西在哪、它能动什么"；任何一步卡住时，都知道下一步该做什么。
- 反面：一打开就看到一堆设置；看不懂的报错；不知道它是不是在工作。

### 1.2 步骤
1. **欢迎页**：主标题"说一句，剩下的交给它"，副标题"先花一分钟做个准备。"按钮【开始】。后台同时开始检查安全空间。
2. **第 1 步：选择 AI 从哪来**（两张并列卡片）
   - "使用在线 AI 服务"：回答更聪明，需要一个连接码，可能按用量付费。
   - "在这台电脑上运行"：不联网、资料不出这台电脑；需要先下载约数 GB，较旧的电脑会比较慢。
   - 选中后进入流程二（授权），完成后自动回到这里。
3. **第 2 步：给它一个文件夹**：默认是 `~/Heybe`，可以修改。说明："它只能在这个文件夹里读写，你的其他文件它碰不到。"按钮【就用这个】/【换一个】。
4. **第 3 步：说第一句话**：进入聊天页，输入框里预填可点击的示例："帮我总结一下这个网页：……"、"帮我比较三款笔记软件"、"用三句话解释……"。
5. 引导在第一次回复成功时结束；之后打开应用直接进入聊天。

### 1.3 状态

| 状态 | 触发 | 用户看到 | 文案 |
|---|---|---|---|
| 加载：检查安全空间 | 欢迎页后台检查 | 页脚有一个小进度点，不挡住操作 | "正在准备安全空间…" |
| 安全空间未就绪 | 沙箱（BoxLite，备选 Lima）未就绪或未启动 | 第 2 步上方出现黄色提示，有【一键安装/打开】和【稍后】两个按钮 | "为了不让它乱动你的文件，需要先装一个小工具（约 2 分钟）。装好前，它只能聊天，不能读写文件。" |
| 安全空间检查失败 | 检查超时或报错 | 同上，加【重试】和【查看详情】（详情里是技术信息，默认折叠） | "安全空间没能启动。可以点重试；还不行就点「查看详情」，把内容发给我们。" |
| 空：聊天页第一次进入 | 没有任何历史 | 示例卡片 + 一行说明 | "交给它一件事，或者先随便聊聊。" |
| 加载：第一次回复 | 发送后 | 打字中的动效；超过 10 秒追加一行说明 | "正在想…"；10 秒后："第一次会慢一点，正在准备。" |
| 出错：第一次回复失败 | 连接失败或额度不足 | 回复气泡位置显示错误卡片 + 【重试】【换一个 AI 服务】 | 按错误类型给出文案，见流程二 2.3 |
| 中途退出 | 引导中关闭窗口 | 下次打开时从上次的步骤继续 | "欢迎回来，从第 2 步继续。" |

### 1.4 边界情况
- 电脑内存低于 16GB 却选了"在这台电脑上运行"：提示"这台电脑运行会比较慢，建议使用在线服务。"可以忽略这条提示继续。
- 选的文件夹没有写入权限，或者是系统目录：提示不可用，必须换一个。
- 已经装过 Ollama 和模型：跳过下载，显示"已经可以用了"。
- 离线状态下选在线服务：提示"现在没有联网"，并推荐本地选项。
- 用户直接关闭窗口：后台服务继续运行；菜单栏图标显示状态。

### 1.5 成功标准
- 干净的 Mac（已有连接码）从打开应用到收到第一次回复的中位时间 ≤ 3 分钟；需要安装安全空间工具时 ≤ 10 分钟。
- 5 位普通用户可用性测试中，至少 4 位无需帮助完成。
- 整个引导过程中，没有出现用词表以外的术语。

### 1.6 验收标准（技术负责人）
- [ ] AC1.1 引导最多 3 步；进度保存在本地，中断后可以续上。
- [ ] AC1.2 欢迎页加载时就异步发起安全空间检测，不阻塞 UI；结果分为 `ready` / `missing` / `failed` 三种状态并有对应界面。
- [ ] AC1.3 安全空间不是 `ready` 时，文件读写类功能禁用并显示原因；纯聊天仍然可用。不允许绕过沙箱直接读写（无"关闭安全空间"的入口）。
- [ ] AC1.4 工作文件夹默认 `~/Heybe`；拒绝 `/`、`/System`、`~/Library` 等路径；选定后作为唯一的挂载目录传给沙箱。
- [ ] AC1.5 所有请求经适配层调用 `/v1`；应用内不加载 FastClaw 的 web/ 资源（打包产物检查）。
- [ ] AC1.6 首次回复超过 10 秒时显示补充文案；超过 60 秒判为失败，进入错误卡片。
- [ ] AC1.7 关闭窗口后，后台服务保持运行（进程检查）；再次打开时恢复到原来的会话。
- [ ] AC1.8 文案 lint：界面字符串中出现 Agent / API / Token / 模型 / 沙箱 / MCP 时，CI 失败（诊断视图除外）。

## 流程二：授权（连接码与权限）

**所属 Issue：** #16 T1.2.1（添加与连接测试）、#3 T0.1.2（钥匙串注入）、#17 T1.2.2（来源标注）、#18 T1.2.3（纯本地模式）、#6 T0.3.1（文件夹权限）

### 2.1 用户目标与应有体验
- 目标："让它能用起来，同时不把我的钥匙或文件交出去。"
- 应有的感受：粘贴一次就好；马上知道成功了没有；清楚地知道连接码存在哪里、谁看得到；随时可以撤回。

### 2.2 步骤
1. 选择服务商（常见的几家 + "其他兼容服务"）。每家旁边有一个【去哪里拿连接码？】链接，打开该服务商的官方页面。
2. 粘贴连接码。输入框默认隐藏内容，有【显示】按钮；粘贴时自动去掉首尾空格。
3. 点【连接】→ 自动测试一次 → 成功后显示"已连上 ✓"，以及这家服务"发送的内容会经过 XX 服务商"的说明。
4. （可选）设置每月花费提醒：默认"花到 $10 时提醒我"。
5. 完成。设置页的"AI 服务"列表里可以查看、更换、断开。
- **文件夹权限**：只有流程一第 2 步那一个文件夹。之后如果助理需要读别的文件，走流程三的确认。

### 2.3 状态与文案

| 状态 | 用户看到的文案 | 操作 |
|---|---|---|
| 空：还没有任何服务 | "还没连接 AI 服务。连上一个就能开始。" | 【连接】【在这台电脑上运行】 |
| 加载：测试中 | "正在试着连一下…"（≤ 15 秒） | 【取消】 |
| 成功 | "已连上 ✓ 你的连接码只保存在这台电脑的钥匙串里。" | 【开始聊天】 |
| 连接码不对 | "这个连接码不对。检查一下是否复制完整，或者在服务商那边重新生成一个。" | 【重新粘贴】 |
| 余额或额度不足 | "这个服务的余额用完了。去服务商那里充值后再试，或者换一个服务。" | 【去充值】【换一个】 |
| 网络不通 | "现在连不上网，检查网络后再试。也可以先用「在这台电脑上运行」。" | 【重试】 |
| 服务商临时出错 | "对方服务暂时不可用（不是你的问题），过一会儿再试。" | 【重试】 |
| 下载本地 AI 中 | "正在下载，约 4.7 GB，已完成 37%。可以先关掉这个窗口，下载会继续。" | 【暂停】 |
| 纯本地模式已开启 | 顶部有常驻标识："只在这台电脑上运行 · 不联网" | 点击查看说明 |

### 2.4 边界情况
- 同一家服务商重复添加：提示"已经连过了，要替换吗？"
- 连接码在使用中失效（被撤销或过期）：在当前对话里提示，并引导重新连接；不自动换到别的服务，除非用户之前选过备用服务。
- 开启纯本地模式时还有在线服务连着：在线服务置灰显示"已暂停"；联网查资料功能关闭，并提示"纯本地模式下不能联网查资料。"
- 用户从设置页断开服务：立即从钥匙串删除连接码；正在进行的事暂停，并提示用户。
- 用户把连接码粘贴进了聊天框：发送前拦截，提示"这看起来像连接码，不要发在聊天里。要去连接页面吗？"

### 2.5 成功标准
- 有连接码的用户从粘贴到连上 ≤ 30 秒；首次连接成功率 ≥ 90%（排除连接码本身无效的情况）。
- 应用数据库、日志、导出包、前端内存快照中都找不到明文连接码。

### 2.6 验收标准
- [ ] AC2.1 连接码只写入 macOS 钥匙串；本地服务启动时通过受限环境变量传给 FastClaw；前端只拿到掩码（`sk-…a1b2`）。
- [ ] AC2.2 6 类提供方（OpenAI、Anthropic、DeepSeek、OpenRouter、Ollama、自定义兼容）各有连接测试；错误映射为 `invalid_key` / `quota` / `network` / `upstream` / `unknown` 五类，各对应 2.3 中的文案。
- [ ] AC2.3 切换模型通过 Agent 配置生效，不依赖请求里的 `model` 字段（#17）。
- [ ] AC2.4 纯本地模式开启后，网络层拒绝所有外发（包括搜索、嵌入、遥测）；有集成测试证明没有静默回退到云端（#18）。
- [ ] AC2.5 日志脱敏：对 `sk-`、`Bearer` 等模式统一打码；CI 中跑密钥扫描。
- [ ] AC2.6 断开服务时同步删除钥匙串条目并通知后台服务；正在使用该服务的任务进入"已暂停"。
- [ ] AC2.7 聊天输入框检测到疑似连接码时，拦截发送。

## 流程三：动作确认（要先问你）

**所属 Issue：** #34 E3.3（完整框架，阶段 3；v1 先做最小版）、#23 T1.4.3（产物待验收）、#24 T1.4.4（预算展示）

### 3.1 用户目标与应有体验
- 目标："它做事前先问我会造成影响的那些，其他的别烦我。"
- 应有的感受：问得少，但问到点子上；一眼看懂"它要做什么、影响什么、能不能撤回"；我说"不"它就真的不做。

### 3.2 v1 需要确认的动作（其余一律不打扰）

| 动作 | 是否询问 | 原因 |
|---|---|---|
| 在"给它用的文件夹"里新建文件 | 不问 | 已授权；文件先进入"等你看一眼"状态 |
| 覆盖或删除文件夹里已有的文件 | 问 | 不可撤回 |
| 读取文件夹以外的文件 | 问（每次，或"这个文件夹以后都可以"） | 超出授权范围 |
| 预计花费超过本次上限 | 问 | 涉及钱 |
| 纯本地模式下需要联网 | 不提供该选项，直接告知做不到 | 维持承诺 |
| 发送、发布、付款 | v1 不具备这些能力 | 阶段 3/4 才开放 |

### 3.3 确认卡结构（出现在对话中，同时在菜单栏提醒）
- 标题：用动词说清楚它要做什么。例："它想覆盖一个文件"
- 内容：对象（`周报.docx`）、改动摘要（"替换为新版本，旧版本会移到「已替换」文件夹"）、能否撤回。
- 按钮：【可以】【不要】；读取类动作多一个【这个文件夹以后都可以】。
- 有效期：30 分钟。过期后显示"这个请求已过期，没有执行。"

### 3.4 状态

| 状态 | 文案 |
|---|---|
| 等待确认 | "等你决定，在你点之前它不会动。" |
| 已同意，执行中 | "好的，正在做…" |
| 已拒绝 | "好，不做了。它会换别的方法，或者告诉你卡在哪里。" |
| 已过期 | "这个请求已过期，没有执行。需要的话可以让它再来一次。" |
| 执行失败 | "没做成：（原因）。文件没有被改动。" |
| 状态不确定（例如执行中重启） | "不确定这一步有没有做完，先暂停了。请看一眼文件后告诉它。" |
| 空：没有待确认事项 | 不显示任何东西（不放空列表） |

### 3.5 边界情况
- 确认后、执行前，内容变了（例如助理改了文件内容）：作废原来的确认，重新询问。
- 同一件事里连续多个覆盖操作：合并成一张卡，逐项列出，允许"全部可以"或单独取消。
- 用户关闭了窗口：确认卡保留，菜单栏图标显示红点；不会因为超时而自动同意。
- 用户在聊天里打字"可以"，而没有点按钮：不算同意，提示用户点卡片上的按钮。
- 网页内容里写着"已获得用户同意"一类的话：一律视为资料，不改变授权。

### 3.6 成功标准
- 一件普通的事里，确认次数中位数 ≤ 1。
- 拒绝或过期之后，执行率为 0（任何入口）。
- 用户调研中，能准确复述"它要做什么"的比例 ≥ 90%。

### 3.7 验收标准
- [ ] AC3.1 确认记录绑定 任务 ID + 动作 + 对象 + 内容摘要哈希 + 过期时间；执行前比对哈希，不一致则作废。
- [ ] AC3.2 拦截在受控工具层实现（不依赖提示词）；沙箱外读取、覆盖、删除只能通过受控工具完成，Worker 没有其他路径（有测试证明）。
- [ ] AC3.3 拒绝或过期后，同一动作通过任何入口（聊天、重试、重启后恢复）都无法执行。
- [ ] AC3.4 覆盖前把旧文件移入 `已替换/`，保证可以撤回。
- [ ] AC3.5 确认状态持久化在任务 SQLite 中；重启后待确认的卡片仍在；执行中断的动作标为"需核查"，不会自动重做。
- [ ] AC3.6 只有点击按钮才算同意；聊天文本、网页和文件内容都不能产生同意记录。
- [ ] AC3.7 预算上限默认值可配置；预计超出时在调用前询问，没有可靠估算时标明"估算"。

## 产品原则 P-SAFE-1：最小动作确认（状态：已由用户于 2026-10-22 确认）
- 所有动作默认在安全空间（隔离环境）中运行，没有关闭入口。
- 敏感操作（删除文件、发送消息、付款等）必须由用户逐次点击确认后才执行；未确认、拒绝或超时一律不执行。
- 适用于全部版本和后续阶段；任何新能力上线前必须声明其是否属于敏感操作。
